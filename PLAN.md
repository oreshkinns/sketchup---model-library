# План разработки расширения SketchUp «Библиотека МАФ»

## 1. Цель

Создать расширение для хранения и вставки моделей малых архитектурных форм (МАФ), которое прежде всего помогает привести открытый проект SketchUp к единому каталогу: находит повторно импортированные модели, предлагает замену на эталонные компоненты и показывает достоверную статистику по всем размещенным МАФ.

**Приоритет:** учет → обнаружение дублей → безопасная замена → управление библиотекой → инструменты расстановки.

## 2. Основные понятия и границы учета

| Понятие | Значение |
| --- | --- |
| Модель каталога | Запись с постоянным `catalog_id`, версией, категорией, названием, файлом `.skp` и техническими метаданными. |
| Определение компонента | `ComponentDefinition` внутри открытого файла SketchUp. Несколько определений могут описывать одну и ту же МАФ. |
| Экземпляр | Конкретное размещение компонента в проекте. Много экземпляров одного определения **не считаются дублями**. |
| Дублирующее определение | Отдельное определение, которое соответствует той же модели каталога или прошло строгую проверку эквивалентности с другим определением. |
| Кандидат на дубль | Геометрически похожая модель, для которой автоматическое объединение небезопасно; решение принимает пользователь. |

Статистика считает **фактические размещения** в открытой модели, включая вложенные компоненты: если контейнер размещен три раза, МАФ внутри него учитывается три раза. Отдельно показываются число определений и число экземпляров. Скрытые экземпляры и скрытые теги входят в общий итог, но отмечаются отдельно. Неиспользуемые определения в статистику размещений не входят. Группы служат контейнерами при обходе; считать группу отдельной МАФ можно только после явной привязки к записи каталога.

## 3. Пользовательские сценарии

1. **Каталог.** Пользователь открывает панель, фильтрует скамейки, урны, светильники и другие категории, просматривает карточку и вставляет `.skp` в проект. Вставленное определение получает `catalog_id`, версию и контрольную сумму записи каталога.
2. **Аудит проекта.** Команда «Анализировать» обходит модель, показывает все распознанные МАФ, неизвестные компоненты и группы дублирующих определений. Для каждой группы видны основания совпадения, количество размещений и места в иерархии проекта.
3. **Замена дублей.** Пользователь выбирает эталон, проверяет список затрагиваемых экземпляров и запускает замену. Расширение сохраняет размещение и свойства экземпляров, сообщает о пропущенных случаях и позволяет отменить операцию стандартным Undo SketchUp.
4. **Быстрая замена.** Пользователь выделяет несколько экземпляров и выбирает модель каталога либо компонент из текущего файла. Перед выполнением видит число замен и ограничения.
5. **Статистика.** Панель показывает количество размещений по категориям и моделям, число уникальных моделей, число определений, найденные дубли и количество замен. Экспорт отчета в CSV — после стабилизации основного учета.
6. **Расстановка.** На следующих этапах пользователь расставляет выбранный компонент с заданным шагом вдоль выбранной линии или распределяет экземпляры по выбранной поверхности с параметрами плотности, отступа, поворота и случайного seed.

## 4. Правила обнаружения дублей

Анализ выполняется в два прохода:

1. **Быстрый проход:** собрать определения и экземпляры; сгруппировать по `catalog_id` и версии; для неизвестных моделей вычислить дешевые признаки (габариты, число граней и ребер, вложенность, материалы). Эти признаки только отбирают кандидатов.
2. **Точная проверка:** для кандидатов сравнить нормализованное содержимое определения в локальных координатах: геометрию и топологию, материалы и текстуры, вложенные компоненты и их трансформации, точку вставки/оси, свойства поведения и значимые атрибуты. Порядок перечисления сущностей не должен влиять на результат. Погрешность координат должна быть фиксированной и задокументированной.

**Классы результата:**

- **Подтвержденный дубль:** совпадают идентификатор и версия каталога, контрольная сумма содержимого и значимые свойства; либо два определения прошли полное строгое сравнение. Только этот класс допускает пакетную замену после подтверждения пользователем.
- **Похожая модель:** совпали лишь имя, габариты или часть геометрических признаков. Показывать для ручного просмотра, не объединять автоматически.
- **Разная модель:** обнаружено различие в геометрии, материалах, вложенности, осях, настройках размещения либо атрибутах, которые могут влиять на поведение.

Имена компонентов сами по себе не доказывают совпадение. Повернутые или масштабированные **экземпляры** одного определения учитываются как одна модель с разными размещениями. Определения с другой системой осей или смещенной локальной геометрией не заменяются автоматически, даже если выглядят одинаково в сцене.

Для динамических компонентов, приклеенных/вырезающих компонентов, зеркальных и вырожденных трансформаций, а также неоднозначных связей с вложенной геометрией нужен отдельный набор проверок. До его прохождения такие случаи переводятся в ручной просмотр или пропускаются с понятной причиной.

## 5. Безопасность замены

- Сначала показать предварительный результат: исходное определение → эталон, число экземпляров, возможные пропуски и изменения на сцене.
- Перед операцией повторно проверить, что модель не изменилась после анализа и все выбранные сущности еще существуют.
- Менять определения у допустимых экземпляров в одной отменяемой операции SketchUp; сохранять трансформацию, материал экземпляра, тег, видимость, имя и пользовательские атрибуты. Сохранение специальных связей проверять отдельно на тестовых моделях.
- Не трогать заблокированные сущности; сообщать о них в отчете. Не удалять исходные определения автоматически: это отдельная явная команда после повторного анализа.
- После замены пересчитать статистику и показать: сколько экземпляров заменено, сколько пропущено, какие группы дублей остались.
- Для полной пакетной замены выполнять предварительную проверку всех экземпляров; при неожиданной ошибке откатывать операцию, чтобы не оставлять частично измененный файл.

## 6. Архитектура

| Модуль | Ответственность |
| --- | --- |
| Регистрация расширения | Загрузка, пункт меню и панель инструментов, пространство имен расширения. |
| Каталог | Чтение локального манифеста, поиск и фильтрация, загрузка `.skp`, хранение метаданных. |
| Обход модели | Рекурсивный учет экземпляров и групп, пути к размещениям, защита от повторного обхода определений при рекурсивных ссылках. |
| Анализ дублей | Быстрые признаки, строгая проверка, классификация и объяснение результата. |
| Замена | Предпросмотр, проверка ограничений, пакетная операция, отчет, Undo. |
| Статистика | Агрегация по категории, модели, определению и месту размещения. |
| Интерфейс | `UI::HtmlDialog`, взаимодействие с Ruby через callbacks, таблицы и карточки. |
| Расстановка | Отдельные команды для линии и поверхности; используют тот же каталог и единые правила учета. |

Начать с **локального каталога**: манифест с метаданными и файлы `.skp` в пользовательской папке вне установленной директории расширения. Сетевой каталог, учетные записи и совместное редактирование не входят в первую версию. Для каталожной модели обязательны стабильный ID и версия; имя файла или имя компонента не используются как идентификатор.

Платформы первой поставки: SketchUp Desktop для Windows и macOS. Точный нижний предел версий фиксируется после проверки API и ручного прогона на выбранных версиях SketchUp.

## 7. Этапы разработки

### Этап 1. Основа расширения и каталог

- Собрать устанавливаемый `.rbz`, зарегистрировать расширение и открыть панель каталога.
- Ввести структуру манифеста, категории, импорт собственных `.skp`, проверку обязательных полей и уникальности `catalog_id`.
- Реализовать вставку компонента и запись метаданных в определение.
- **Готово, когда:** пользователь устанавливает расширение, видит каталог, добавляет модель и размещает ее в проекте с сохранением привязки к записи каталога.

### Этап 2. Учет и статистика — ядро MVP

- Реализовать обход вложенных размещений, распознавание каталожных и неизвестных компонентов, подсчет по категориям и определениям.
- Показать таблицу моделей с количеством экземпляров и определений; дать переход/выделение размещений в сцене там, где это допускает контекст SketchUp.
- Обновлять отчет по явной команде «Анализировать» и после операций расширения; добавить индикатор устаревшего отчета после внешних изменений модели.
- **Готово, когда:** цифры совпадают с ручным подсчетом на контрольных файлах с вложенностью, повторно используемыми контейнерами, скрытыми и неиспользуемыми определениями.

### Этап 3. Поиск дублей — ядро MVP

- Добавить быстрый отбор и строгую проверку кандидатов, уровни достоверности и объяснение причин совпадения/расхождения.
- Проверить модели с одинаковыми именами и разной геометрией, одинаковой геометрией и разными материалами, разными осями, вложенными моделями и разными версиями каталога.
- **Готово, когда:** заведомо разные модели не попадают в класс «подтвержденный дубль», а повторно импортированные эквивалентные определения находятся.

### Этап 4. Замена дублей — завершение MVP

- Добавить выбор эталона, предварительный просмотр, пакетную замену, отчет о пропусках и отмену одной командой Undo.
- Проверить сохранение свойств экземпляров и отсутствие изменений вне выбранных размещений.
- **Готово, когда:** после замены число размещений не меняется, число дублирующих определений в использовании уменьшается, Undo возвращает исходное состояние, а повторный анализ подтверждает результат.

### Этап 5. Быстрая замена и отчет

- Добавить замену выделенных компонентов на выбранную модель с теми же проверками и предпросмотром.
- Добавить CSV-экспорт текущего отчета: ID, название, категория, определения, экземпляры, статус распознавания и статус дублей.
- **Готово, когда:** замена работает для выделения из нескольких экземпляров, а CSV соответствует показанной статистике.

### Этап 6. Расстановка

- Сначала реализовать размещение по линии с шагом, направлением и предпросмотром.
- Затем добавить распределение по поверхности с плотностью, отступом от границ, ограничением пересечений и воспроизводимым seed.
- **Готово, когда:** все созданные экземпляры сразу появляются в статистике и вся расстановка отменяется одной операцией Undo.

## 8. Проверка качества

Минимальный набор контрольных файлов `.skp`: пустой проект; несколько экземпляров одного определения; два независимых импорта той же модели; похожие скамейки с разными деталями; разные материалы/текстуры; вложенные МАФ в повторяемом контейнере; скрытые/заблокированные компоненты; зеркальные и масштабированные экземпляры; большой проект с тысячами экземпляров.

Проверить на каждой поддерживаемой версии SketchUp: установку `.rbz`, работу панели, время анализа большого файла, совпадение чисел учета, отсутствие ложных автоматических совпадений, замену и Undo, сохранение/повторное открытие проекта. Для алгоритма сравнения и агрегации написать автоматические тесты на небольших геометрических фикстурах; операции SketchUp и интерфейс дополнительно проверять в самом приложении.

## 9. Решения перед реализацией

1. Утвердить состав первой библиотеки: категории, ориентировочное число моделей, права на их распространение и правила именования.
2. Определить точные версии SketchUp, которые нужно поддерживать в первой поставке.
3. Уточнить, нужно ли учитывать **любые** компоненты проекта или только распознанные МАФ: предложенный план показывает обе группы, но сводные показатели МАФ строит по распознанным моделям.
4. Зафиксировать, какие пользовательские атрибуты и свойства динамических компонентов являются обязательными для сохранения при замене.
