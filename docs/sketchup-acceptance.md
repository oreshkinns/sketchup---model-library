# Ручная приемка в SketchUp

Эта процедура дополняет автоматические Ruby-тесты. Проверки, зависящие от SketchUp, Ruby API, HtmlDialog, сохранения `.skp` и Undo, выполняются внутри приложения. Для первого прогона поддерживаемый диапазон из README — SketchUp Desktop 2021–2026 на Windows и macOS.

## Подготовка

1. Соберите расширение из корня репозитория командой `./build.sh`. Установите полученный `dist/maf_library-*.rbz` через **Extensions → Extension Manager → Install Extension**. Если SketchUp предупредит о неподписанном архиве, разрешите установку для локальной приемки.
2. Перезапустите SketchUp, откройте **Extensions → МАФ Каталог** и убедитесь, что панель загрузилась. Запишите точную версию SketchUp, ОС, архитектуру и версию RBZ.
3. Создайте новый пустой файл модели. Не запускайте генератор в проекте с данными: он отказывается изменять непустую активную модель.
4. Откройте Ruby Console (**Window → Ruby Console** на Windows; **Window → Ruby Console** на macOS), выполните `load '/absolute/path/to/scripts/sketchup_acceptance.rb'`, заменив путь на путь в вашей системе.

Генератор не был запущен в этой среде: SketchUp и контрольные `.skp` здесь отсутствуют. Он строит модели непосредственно через Ruby API SketchUp при ручном прогоне.

## Контрольные проекты

Сохраните каждый fixture в отдельный `.skp`. Перед созданием следующего выберите **File → New**.

| Ruby Console команда | Содержимое и ожидаемые результаты анализа |
| --- | --- |
| `MafLibraryAcceptance.save_empty` | Пустой проект: 0 размещений, 0 определений, 0 уникальных моделей, 0 групп дублей. |
| `MafLibraryAcceptance.build_standard` | Сценарии из плана: независимые одинаковые импорты, похожая модель с внутренним ребром, одинаковая геометрия с разными материалами и текстурой, повторный вложенный контейнер, скрытые и заблокированный экземпляры, масштабированный и зеркальный экземпляры. Ожидается 13 размещений, 10 определений, 9 уникальных моделей. Только пара одинаковых импортов должна быть подтвержденной группой; похожая геометрия и варианты материалов могут быть кандидатами на ручную проверку, но не должны разрешать автоматическую замену. В таблице ожидаются 1 скрытый экземпляр и тег `Acceptance hidden tag`. Вложенный МАФ должен иметь 2 размещения по двум путям через контейнер. |
| `MafLibraryAcceptance.build_large` | 1 500 экземпляров одного определения: 1 500 размещений, 1 определение, 1 уникальная модель, 0 дублей. Используйте для замера времени анализа. |

Генератор сохраняет файл через системный диалог. Для пустого проекта используйте команду `save_empty`; для каждого метода сначала открывайте новую модель.

## Прогон для каждого SketchUp и каждой ОС

Выполните следующие шаги отдельно на каждой целевой комбинации SketchUp 2021, 2022, 2023, 2024, 2025, 2026 и Windows/macOS. Укажите «не проверено», если нужной версии или платформы нет под рукой; не переносите результат между версиями.

1. **Установка и панель.** Установите RBZ, перезапустите SketchUp и откройте панель. Проверьте, что она не падает при запуске и показывает кнопку анализа.
2. **Пустой файл.** Откройте `acceptance-empty.skp`, запустите анализ и сравните числа с таблицей. Повторите анализ: пустой отчет должен оставаться пустым.
3. **Счет и группы дублей.** Откройте `acceptance-standard.skp`, запустите анализ. Сверьте общие числа, скрытый экземпляр/тег, два вложенных размещения и имена моделей. Убедитесь, что одинаковые импорты указаны как подтвержденный дубль, а похожая скамья и отличающиеся материалы не отмечены как подтвержденные.
4. **Замена и Undo.** На странице дублей выберите подтвержденную группу одинаковых импортов и назначьте один компонент эталоном. Запишите число затрагиваемых размещений и предупреждения, выполните замену. Повторите анализ: два исходных определения должны стать одним, геометрия и положение оставшегося экземпляра — сохраниться. Выполните один стандартный Undo SketchUp и повторите анализ: исходные два определения и placements должны восстановиться. Затем попробуйте заменить кандидатную группу по похожему имени/габаритам; интерфейс не должен разрешать автоматическую замену неподтвержденной группы.
5. **Большой файл и время.** Откройте `acceptance-large-1500.skp`. Сравните число с 1 500. Нажмите анализ три раза после завершения предыдущего прохода и запишите каждый показанный показатель времени; в отчет заносите медиану и худший результат. Запишите время открытия проекта и были ли зависания/ошибки UI. Сравнивайте результаты только на одной и той же машине и конфигурации.
6. **Сохранение и повторное открытие.** Сохраните `acceptance-standard.skp` под новым именем, закройте его, откройте снова и выполните анализ. Числа, сведения о материалах и дублях должны совпасть с результатом до закрытия. Повторите после сценария с заменой и после Undo.
7. **Отчет о прогоне.** Сохраните версию SketchUp, ОС, архитектуру, версию расширения, fixture, ожидаемые и фактические числа, время анализа, результат замены/Undo, результат повторного открытия и скриншот любой ошибки.

## Ограничения контрольной сцены

- Это минимальная синтетическая геометрия: она проверяет базовый учет граней/материалов и трансформаций, но не заменяет производственные проекты с динамическими компонентами, текстурами высокого разрешения, приклеенными компонентами, нестандартными атрибутами и сложной топологией.
- Текстура fixture — временный 1×1 PNG; SketchUp должен встроить ее в сохраненный `.skp`. Проверьте материал в окне материалов до/после сохранения, так как упаковка текстуры и превью отличаются между платформами и версиями.
- Зеркальный экземпляр включен для проверки учета. Замену зеркальных экземпляров не следует ожидать успешной: реализация должна сообщить о ручной проверке/ограничении, а не испортить модель.
- Проверка коллизий раскладки использует консервативные круговые оценки габаритов новых и существующих экземпляров в активном контексте. Она учитывает масштабирование и зеркальные трансформации и включает скрытые/заблокированные экземпляры. Это приближение по ограничивающим габаритам: оно может отклонить свободную точку и не гарантирует точную проверку пересечения сложной геометрии. Вложенные экземпляры вне активного контекста и геометрия самих экземпляров не проверяются как точные тела.
- Большая сцена содержит 1 500 экземпляров одного простого определения, поэтому она проверяет масштабирование числа размещений, но не тяжелую геометрию или большой объем текстур.
- Расстановка по поверхности, плотность, отступ, коллизии и повторяемый seed имеют отдельные алгоритмические проверки; дополнительно нужно вручную проверить предпросмотр, размещение на грани с внутренним отверстием, отказ от точек у уже размещенных компонентов и один Undo на реальных гранях SketchUp.
- Генератор создает фикстуры, но не запускает панель, не проверяет UI и не подтверждает успешность замены. Эти шаги выполняются вручную.
