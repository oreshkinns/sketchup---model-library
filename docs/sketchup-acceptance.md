# Ручная приемка в SketchUp

Эта процедура дополняет автоматические Ruby-тесты. Проверки, зависящие от SketchUp, Ruby API, HtmlDialog, сохранения `.skp` и Undo, выполняются внутри приложения. Для первого прогона поддерживаемый диапазон из README — SketchUp Desktop 2021–2026 на Windows и macOS.

## Подготовка

1. Соберите расширение из корня репозитория командой `./build.sh`. Установите полученный `dist/maf_library-*.rbz` через **Extensions → Extension Manager → Install Extension**. Если SketchUp предупредит о неподписанном архиве, разрешите установку для локальной приемки.
2. Перезапустите SketchUp, откройте **Extensions → МАФ Каталог** и убедитесь, что панель загрузилась. Запишите точную версию SketchUp, ОС, архитектуру и версию RBZ.
3. Создайте новый пустой файл модели. Не запускайте генератор в проекте с данными: он отказывается изменять непустую активную модель.
4. Откройте Ruby Console (**Window → Ruby Console** на Windows; **Window → Ruby Console** на macOS), выполните `load '/absolute/path/to/scripts/sketchup_acceptance.rb'`, заменив путь на путь в вашей системе.

Генератор пока не был запущен в SketchUp. Он строит модели непосредственно через Ruby API SketchUp при ручном прогоне.

## Контрольные проекты

Сохраните каждый fixture в отдельный `.skp`. Перед созданием следующего выберите **File → New**.

| Ruby Console команда | Содержимое и ожидаемые результаты анализа |
| --- | --- |
| `MafLibraryAcceptance.save_empty` | Пустой проект: 0 размещений, 0 определений, 0 уникальных моделей, 0 групп дублей. |
| `MafLibraryAcceptance.build_standard` | Сценарии из плана: независимые одинаковые импорты, похожая модель с внутренним ребром, одинаковая геометрия с разными материалами и текстурой, повторный вложенный контейнер, скрытые и заблокированный экземпляры, масштабированный и зеркальный экземпляры. Ожидается 13 размещений, 10 определений, 9 уникальных моделей. Только пара одинаковых импортов должна быть подтвержденной группой; похожая геометрия и варианты материалов могут быть кандидатами на ручную проверку, но не должны разрешать автоматическую замену. В таблице ожидаются 1 скрытый экземпляр и тег `Acceptance hidden tag`. Вложенный МАФ должен иметь 2 размещения по двум путям через контейнер. |
| `MafLibraryAcceptance.build_large` | 1 500 экземпляров одного определения: 1 500 размещений, 1 определение, 1 уникальная модель, 0 дублей. Используйте для замера времени анализа. |

Генератор сохраняет файл через системный диалог. Для пустого проекта используйте команду `save_empty`; для каждого метода сначала открывайте новую модель.

## Прогон для каждого SketchUp и каждой ОС

Выполните следующие шаги отдельно на каждой целевой комбинации SketchUp 2021, 2022, 2023, 2024, 2025, 2026 и Windows/macOS. Укажите «не проверено», если нужной версии или платформы нет под рукой; не переносите результат между версиями.

1. **Установка и панель.** Установите RBZ и перезапустите SketchUp. Проверьте, что панель инструментов **МАФ Каталог** появилась с иконкой и открывает каталог. Перетащите ее в другое место, перезапустите SketchUp и проверьте сохранение положения. Скрытие через меню панелей инструментов должно сохраняться при следующем запуске. Откройте каталог на пустой и крупной модели: окно должно отобразиться до начала анализа и показывать кнопку анализа.
2. **Пустой файл.** Откройте `acceptance-empty.skp`, запустите анализ и сравните числа с таблицей. Повторите анализ: пустой отчет должен оставаться пустым.
3. **Счет и группы дублей.** Откройте `acceptance-standard.skp`, запустите анализ. Сверьте общие числа, скрытый экземпляр/тег, два вложенных размещения и имена моделей. Убедитесь, что одинаковые импорты указаны как подтвержденный дубль, а похожая скамья и отличающиеся материалы не отмечены как подтвержденные.
4. **Замена и Undo.** На странице дублей выберите подтвержденную группу одинаковых импортов и назначьте один компонент эталоном. Запишите число затрагиваемых размещений и предупреждения, выполните замену. Повторите анализ: два исходных определения должны стать одним, геометрия и положение оставшегося экземпляра — сохраниться. Выполните один стандартный Undo SketchUp и повторите анализ: исходные два определения и placements должны восстановиться. Затем попробуйте заменить кандидатную группу по похожему имени/габаритам; интерфейс не должен разрешать автоматическую замену неподтвержденной группы.
5. **Большой файл и время.** Откройте `acceptance-large-1500.skp`. Сравните число с 1 500. Нажмите анализ три раза после завершения предыдущего прохода и запишите каждый показанный показатель времени; в отчет заносите медиану и худший результат. Запишите время открытия проекта и были ли зависания/ошибки UI. Сравнивайте результаты только на одной и той же машине и конфигурации.
   После анализа откройте страницу дублей, войдите в компонент и выйдите без изменения геометрии. Запишите, запускался ли повторный анализ и оставалось ли окно отзывчивым. Затем измените геометрию внутри компонента: отметка об устаревшем отчёте должна появиться без задержки, а повторный анализ — завершиться. Повторите на копии крупного рабочего проекта.
6. **Сохранение и повторное открытие.** Сохраните `acceptance-standard.skp` под новым именем, закройте его, откройте снова и выполните анализ. Числа, сведения о материалах и дублях должны совпасть с результатом до закрытия. Повторите после сценария с заменой и после Undo.
7. **Отчет о прогоне.** Сохраните версию SketchUp, ОС, архитектуру, версию расширения, fixture, ожидаемые и фактические числа, время анализа, результат замены/Undo, результат повторного открытия и скриншот любой ошибки.

## Ограничения контрольной сцены

- Это минимальная синтетическая геометрия: она проверяет базовый учет граней/материалов и трансформаций, но не заменяет производственные проекты с динамическими компонентами, текстурами высокого разрешения, приклеенными компонентами, нестандартными атрибутами и сложной топологией.
- Текстура fixture — временный 1×1 PNG; SketchUp должен встроить ее в сохраненный `.skp`. Проверьте материал в окне материалов до/после сохранения, так как упаковка текстуры и превью отличаются между платформами и версиями.
- Зеркальный экземпляр включен для проверки учета. Замену зеркальных экземпляров не следует ожидать успешной: реализация должна сообщить о ручной проверке/ограничении, а не испортить модель.
- Проверка коллизий раскладки использует консервативные круговые оценки габаритов новых и существующих экземпляров в активном контексте. Она учитывает масштабирование и зеркальные трансформации и включает скрытые/заблокированные экземпляры. Это приближение по ограничивающим габаритам: оно может отклонить свободную точку и не гарантирует точную проверку пересечения сложной геометрии. Вложенные экземпляры вне активного контекста и геометрия самих экземпляров не проверяются как точные тела.
- Большая сцена содержит 1 500 экземпляров одного простого определения, поэтому она проверяет масштабирование числа размещений, но не тяжелую геометрию или большой объем текстур.
- Расстановка по поверхности, плотность, отступ, коллизии и повторяемый seed имеют отдельные алгоритмические проверки; дополнительно нужно вручную проверить предпросмотр, размещение на грани с внутренним отверстием, отказ от точек у уже размещенных компонентов и один Undo на реальных гранях SketchUp.
- Генератор создает фикстуры, но не запускает панель, не проверяет UI и не подтверждает успешность замены. Эти шаги выполняются вручную.

## Локальное распознавание и библиотека: дополнительная приёмка

Перед этим прогоном выберите отдельную пустую **личную** папку библиотеки: анализ автоматически сохраняет туда новые подтверждённые модели. Запишите содержимое личной и общей папок до и после каждого шага. Автоматические тесты не заменяют эти проверки в SketchUp.

1. **Старт и выбор без анализа.** Откройте новый проект и панель: первой активна «Библиотека». До анализа карточки показывают «—». Выделите один компонент, нажмите «Добавить выделенный в SketchUp»; проверьте предложенные имя, раздел и выбор personal/shared. Повторите через контекстное меню SketchUp, затем с одной группой. Нулевое и множественное выделение должны дать понятную ошибку. Импорт файла `.skp` остаётся отдельным действием.
2. **Повторное добавление и копия.** Повторное добавление связанной модели в ту же библиотеку открывает существующую карточку. Попытка добавить в другую библиотеку не делает копию молча. Нажмите «Создать копию выделенного…», укажите другое имя/раздел/библиотеку; исходная карточка и файл остаются, новая запись появляется только после подтверждения.
3. **Автосохранение и полный матч.** Добавьте компонент со скамейкой подходящего имени и габаритов либо подтвердите его вручную. Анализ создаёт один `.skp` и одну карточку в личной папке. Повторный анализ, повторное открытие проекта и независимая точная копия определения не создают дубликат карточки. Общая и облачная библиотеки не изменяются автоматически.
4. **Неоднозначность.** Подготовьте две подтверждённые карточки с одинаковым полным отпечатком и новый несвязанный экземпляр. Показывается предупреждение о нескольких точных карточках; размещения не присваиваются произвольно одной из них. Обычное добавление не выбирает карточку автоматически. Для явного решения выделите один экземпляр в сцене, создайте отдельную копию через соответствующую кнопку и проверьте связь с новой карточкой. Ручная привязка к выбранной существующей карточке отдельным действием пока не реализована.
5. **Параметры и решения.** У кандидата показаны все имена, теги, раздел, габариты, грани/рёбра/материалы, глубина вложения, особенности и атрибуты. Причина и предупреждения отображаются отдельно. «Подтвердить МАФ», «Не МАФ», «Сбросить решение» передают решение всем размещениям определения, показывая число и все пути. Проверьте Undo и повторный анализ каждого решения. CSV и разделы должны совпадать с классификацией UI.
6. **Дерево.** Поместите один компонент в две разные ветки; в одной ветке разместите несколько экземпляров. Ветви сворачиваются независимо; число в строке уже учитывает фактические размещения и не умножается повторно на число родителей. Непомеченная группа — контейнер без действий. «Только МАФ» скрывает остальных, сохраняя путь родителей. Подтверждённый родитель и его подтверждённый ребёнок учитываются отдельно. Проверьте Ctrl/Cmd, Shift, Enter и раскрытие клавиатурой.
7. **Область действия.** Выберите МАФ только в одной ветке и откройте переименование, раздел, удаление или замену. Предпросмотр должен перечислять все размещения определения и пути по всему проекту. Для замены дополнительно дождитесь серверной проверки ограничений. Измените модель при открытом подтверждении: оно блокируется и требует открыть действие заново. Проверьте прежние Undo, замену дублей, расстановку, линию и поверхность.
8. **Счётчики и карточки.** Несколько определений, связанных с одной карточкой, суммируются. Одинаковые ID в личной/общей библиотеках не смешивают числа. Переключение проекта и изменение модели сразу дают «—» до свежего отчёта; свежий отчёт без экземпляров показывает 0, карточка остаётся. Проверьте обновление миниатюры/тегов без потери текущего числа размещений.
9. **Расхождение и ошибка записи.** Измените геометрию связанного определения: сохранённый файл остаётся прежним, появляется предупреждение и «Обновить версию…». Проверьте явный выбор определения и увеличение версии после подтверждения. Запретите запись в тестовую личную папку: отчёт остаётся доступным, видна причина ошибки и «Повторить сохранение в личную библиотеку». Восстановите запись и повторите — не должно появиться лишних карточек.
10. **Пакет.** Сверьте `maf_library/ui.html` в установленном RBZ с preview.html: библиотека первая, одинаковые кнопки, дерево и счётчики. Зафиксируйте точную версию SketchUp/ОС; пока этот список не выполнен в приложении, комбинация считается «не проверено».

### Undo при служебной привязке и SketchUp 2021.0

- Автоматическое сохранение и привязка используют отдельную обычную операцию SketchUp. Это намеренный дополнительный шаг Undo: отложенный таймер не может надёжно присоединить атрибуты к исходной операции. Событие `onTransactionStart` приходит лишь при завершении транзакции и не доказывает, что сейчас нет открытой операции. Прозрачные операции здесь не используются, поэтому ошибка привязки не отменяет пользовательскую операцию.
- Для вручную подтверждённого определения с неполной сигнатурой откройте панель, дождитесь карточки и отмените служебную привязку. После 500 мс Undo не должен снова становиться «Привязать МАФ к библиотеке»; Redo должен оставаться доступным. Повторный анализ и закрытие/открытие панели в той же живой модели также сохраняют Redo. Карточка и количество размещений восстанавливаются из памяти без записи новых атрибутов. Следующий обычный пользовательский commit снова разрешает постоянную привязку.
- Проверьте два отдельных шага Undo после подтверждения: сначала служебную привязку, затем само подтверждение. Redo обоих шагов должен вернуть решение, связь и количество без второй карточки. После отмены удаления экземпляра проверьте, что Redo снова удаляет его, а счётчик меняется 0 → 1 → 0.
- Проверьте запуск таймера во время долгой нативной операции/инструмента и события других расширений. Модульные тесты моделируют историю операций, но не подтверждают нативное объединение событий и открытых транзакций.
- Для двух вручную подтверждённых определений с неполными сигнатурами отмените служебные привязки, сохраните проект и откройте его заново. Карточки, личная/общая область и количество размещений должны восстановиться без новых файлов; предупреждение непроверенной геометрии остаётся. Повторите после первого сохранения безымянного проекта и **Сохранить как** при закрытой панели. До закрытия модели Redo должен сохраняться, новых служебных операций быть не должно. На каждой целевой версии проверьте, что `onPostSaveModel` видит окончательные `model.path` и `model.guid`, а `definition.persistent_id` сохраняется при открытии. Индекс находится в личной папке `recovery/`; заменённый другим проектом файл с тем же путём и перемещённая вне SketchUp копия не должны получать старую связь только по совпадению ID. Ошибка записи индекса показывается и требует повторного анализа до закрытия проекта. Нативная проверка этих случаев пока не выполнена.
- В SketchUp **2025–2026** сравните две независимые модели с одинаковой геометрией и цветом, но различной шероховатостью/металличностью без обычной текстуры: они не должны считаться точным совпадением каталога. Изменение PBR-настроек связанной модели должно показать расхождение. Затем добавьте только карту шероховатости, металличности, нормалей или затенения: автоматическое точное совпадение и автоматическая замена дублей запрещены. В SketchUp 2021 проверьте обычные материалы без этих API. Нативная проверка пока не выполнена.
- В SketchUp **2021.0** проверьте открытие HtmlDialog, передачу `ready`, карточки, дерево, подтверждения и обновление версии. Автоматический тест проверяет грамматику ECMAScript 2018 и работу без `Array.prototype.flatMap`; он не заменяет запуск CEF 64 в приложении.
- В SketchUp **2021** перед обновлением версии запишите `definition.path`, состав корневых сущностей и активный путь редактирования. Повторите для компонента, группы и неиспользуемого определения. После успешного обновления и ошибки записи путь исходного определения и состав модели должны сохраниться; временные экземпляры и определения экспорта не должны остаться. Проверьте геометрию сохранённого файла и Undo/Redo: временный экспорт выполняется отдельной отменяемой операцией и не использует исходное определение для `save_as`.
- Для неравных размеров X/Y/Z сверяйте карточку и параметры распознавания как ширина × глубина × высота: вертикальная высота соответствует Z. При одинаковом ID карточек в личной и общей папках обновление выбранной карточки должно менять только её библиотеку.
